# 文旅数据标注平台（web/）

在一个页面里完成 **数据资产 → 需求发布 → 切块下发 → 标注 → 审核 → 交付** 的全流程：

- **数据资产**：两类 AI 蒸馏数据。
  - 蒸馏数据：规则引擎蒸馏的 5 个明细数据集与 5 个训练集，即原有的数据管理功能，可查看、在线修改、导出 JSONL。
  - AI 生成：合并自 Lumos，由大模型按数据规格生成会话明细与训练集。
- 所有资产都可以在需求区作为数据源发布标注需求，经人工标注、审核后交付。
技术栈为 Next.js 16 + HeroUI v3，表格与分页沿用客户提供的 `Table` / `Pagination` 写法。数据默认存放在 SQLite 中，使用 Node 内置的 `node:sqlite`，不需要另外安装数据库。

## 一、启动

```bash
# 1) 在项目根目录把全部数据导入 SQLite（第一次需要，约 5 分钟，生成 web/data/{ods,dim,dwd,dws,ads}.db，约 5.2GB）
python -m distill.build_db

# 2) 启动页面（需要 Node.js ≥ 22.13）
cd web
npm install
npm run build
npm start            # 浏览器打开 http://localhost:3000，未登录会自动跳到登录页
```

以后再启动只需要执行 `cd web && npm start`。

`ads.db` 中已有标注数据时，`build_db` 会拒绝重建，以防标注条目引用的行号失效。确实要重建请加 `--force`。重建只替换数据表，用户、项目、标注成果等平台表会保留。

## 三、业务流程

0. **数据资产**（需求员 / 超级管理员）
   - 查看蒸馏数据。
   - 新建 AI 生成任务，生成明细或训练集资产。
   - 在资产详情中可以直接点「发布标注需求」。
1. **需求员**
   - 在「项目区」创建项目。
   - 在「需求区」发布标注需求：
     - **可以同时指定多个数据源**：蒸馏数据和 AI 生成资产可以混选。
     - 训练集可以限定训练/验证/测试集。
     - 每个数据源都可以设置条数上限。
     - 填写标注标准。
2. **管理员**
   - 在「需求区」接收需求，或者填写原因后驳回。
   - 接收后点击「下发」，系统按 **5000 条/块**切分，分块进入标注区的待认领列表。
3. **标注员**
   - 在「标注区」认领分块。认领是原子操作，**已被认领的分块不能再被认领**。
   - 进入分块后逐条标注：
     - **确认正确**：内容没有改动时，记为「正确」。
     - **保存修正**：内容有改动时，自动记为「已修正」。
     - **标为无效剔除**：交付时剔除这一条。
     - **AI 再标**：大模型按标注标准给出建议，填入编辑区，标注员确认后才会保存。
   - 可以退回分块，退回后已标注的内容会保留，分块回到待认领。
   - 全部标完后提交审核。
4. **审核员**
   - 在「审核区」领取待审核的分块，系统会**随机抽检 5%（至少 50 条）**。
   - 对抽检条目逐条判定：合格；不合格并直接修改；不合格并剔除。
   - 可以发表审核意见，针对整个分块或某一条数据都可以。
   - 抽检全部审完后可以「审核通过」；也可以「退回返修」，此时必须填写意见，标注员会在返修页顶部看到意见，并能筛选出不合格和有意见的条目。
5. **交付**
   - 需求的全部分块审核通过后，管理员在「交付区」点击交付。
   - 需求员在交付区看到自己的需求已交付，确认交付后可以下载：
     - **JSONL**：可直接用于训练，已剔除无效条目，包含所有人工修正。
       - 训练样本：每行为 `{"messages":[...]}`。
       - 明细数据：每行一个对象。
       - AI 生成训练集：每轮一行 `{"sample_id","conversation_id","messages"}`，与 Lumos 格式一致。
       - AI 生成明细：每行一段会话。
     - **明细 CSV**：每一条的来源、标注结论、审核结论、标注人、审核人以及最终内容，包含被剔除的条目。

## 四、JSON 可视化编辑

标注与审核作业台中的数据，都通过 JSON 可视化编辑器渲染和编辑：

- 对象和数组以树形展开，可以折叠，可以增删字段和元素。明细数据的字段固定，不允许增删。
- 字符串、数字、布尔值、null 都可以就地编辑，长文本自动切换为多行输入框。
- **内容本身是 JSON 的字符串会自动展开为嵌套树**。比如训练样本中的 user 输入、answer 结果，编辑后会按原数据的 JSON 风格序列化回字符串。
- 编码字段以下拉框显示「编码-含义」，字段旁边显示中文注释。
- 可以切换到「源码」模式直接编辑 JSON 文本，带实时语法校验。
- 训练样本拆成 system（只读）、user、`<thought>`、`<answer>` 四部分分别编辑，并实时校验格式和业务约束。
- 可以「对照原始内容」，左右并排查看原始内容和当前内容。

保存时服务端会再次校验，不合规的内容不能保存：
- 训练样本：校验 messages 结构，以及定价限价、投放预算闭合、归因加和、推荐商品必须在库存内等业务约束。
- 明细数据：校验字段集合、类型、编码取值范围，以及编码字段与名称字段是否一致。

## 五、数据资产 · AI 生成（合并自 Lumos）

原 Lumos 的生产能力已整体移植进平台，不需要再单独部署 Lumos，模板引擎与 Lumos 逐行对拍一致。生成的数据不直接交付，统一进入本平台的标注审核流程。

### 1. 生成配置

| 配置 | 说明 |
|---|---|
| 模型管理 | 任何 OpenAI 兼容接口，如 DeepSeek、OpenAI、火山方舟、通义、自建网关 |
| 数据规格 | 一类产出的完整定义 |
| 提示词 | 每次修改自动留存版本，可查看、恢复历史版本 |
| 业务字典 | 意图体系、槽位、覆盖类目、会话形态、景区池等 |

**模型管理**
- 协议 `auto` 先试 `/chat/completions`，不支持时自动切换 `/responses`。
- 限流、5xx 和网络错误会指数退避重试。
- API Key 只显示掩码。
- 支持连通性测试。

**数据规格**定义以下内容：
- 维度轮转与筛选。
- 去重字段。
- 训练样本模板：`messages`、`{{变量}}`、历史对话拼接。
- 校验器：非空、JSON 键、整数范围、字数上限。
- 展示与导出字段。

新增一类生成数据只需新增规格与提示词，**不改代码**。预置 6 个规格来自 Lumos：智能客服会话（明细 / 训练集）、讲解评价（明细 / 训练集）、个性化讲解（明细 / 训练集）。

**提示词版本**：生成任务执行时固化版本号，任何一条数据都能回溯到生成时的确切提示词。

**业务字典**：维度从字典取值，提示词以 `{{dict_编码}}` 引用整张字典。

### 2. 生成任务

**明细生成**
- 按规格维度轮转组织提示词，例如 类目 × 会话形态。
- 并发批量调用。
- 会话按首轮内容去重；会把已生成的内容放进提示词，防止重复。
- 不超过目标会话数。
- 连续 3 轮没有新增会自动结束，以免空跑消耗 token。

**AI 预标注**
- 对一份明细资产逐轮调用模型产出字段，例如意图槽位与回复、评分与评语。
- 按样本模板组装为训练样本，多轮会话自动带上历史对话。
- 来源范围可以选：
  - 「全部会话」：机器产出。
  - 「仅已交付的标注结果」：使用人工审核修正后的明细，并跳过被剔除的会话。

**执行与续跑**
- 任务后台执行，页面实时显示进度、token 用量与日志。
- 可以停止后继续执行：在原资产上续跑。
- 「重新执行」会产出新版本资产。
- 服务重启时，执行中的任务会标记为中断，可继续执行。

### 3. 进入标注审核

- 每份生成资产自动登记为数据源 `gen_asset_<资产ID>`，在需求区的「AI 生成资产」分组中选择。**标注单位为会话**。
- 明细会话以问答预览 + JSON 可视化编辑。
- 训练集会话逐轮编辑 AI 字段，右侧**实时按规格模板组装并预览最终训练样本**；修改问答后，后续轮次的历史对话自动更新。
- 保存时按规格校验器校验，不合规不能保存。会话编号与轮次数不可改。
- **AI 再标**：
  - 训练集：沿用生成时的模型与固化版本的提示词，并附上需求的标注标准，逐轮重新预标注。
  - 明细：按标注标准与原生成要求检查并修正。
  - 蒸馏数据的 AI 再标：使用模型管理中的默认模型。
- 资产详情页可以导出未经审核的机器产出：训练集 JSONL、明细 CSV，格式与 Lumos 一致。已被需求引用的资产不能删除。

### 4. 导入 Lumos 历史数据

```bash
# 先启动一次页面（建好平台表），再执行；可重复执行，已导入的资产会跳过
python web/scripts/import_lumos.py --lumos /path/to/labelumos/data/lumos.db
```

导入内容：
- 模型（含 API Key，`--no-keys` 不导入）。
- 规格、提示词（含全部历史版本）、字典。
- 任务与日志、资产、会话、样本。

导入规则：
- **样本取 Lumos 中人工修改后的版本**。
- **Lumos 中审核驳回的会话默认不导入**（`--keep-rejected` 保留）。
- 平台已有的同编码配置默认保留平台版本（`--overwrite` 覆盖）。
- 提示词内容不同时，Lumos 的提示词以 `<编码>_lumos` 导入，保证历史资产可回溯。

已验证：
- 导入后的训练集资产走完 需求 → 标注 → 审核 → 交付，交付 JSONL 与 Lumos 自身导出**逐行一致**。

## 六、数据库表（按客户数仓命名规范）

页面启动时会把 5 个 SQLite 文件挂载为 `ods`、`dim`、`dwd`、`dws`、`ads` 五个库，所有 SQL 一律使用「库.表」写法：

| 库.表 | 内容 |
|---|---|
| `ods.ods_prd_ctrip_attraction_ticket_df` | 携程景区票务原始数据（35.8 万行，原样落库） |
| `dim.*` / `dwd.*` / `dws.*` | 6 张明细数据表，在规范字段之外增加管理字段 `row_id`、`is_edited` |
| `ads.ads_llm_sft_sample_f` | 5 个模型的 SFT 训练样本（50 万条） |
| `ads.ads_llm_data_edit_log_f` / `ads.ads_llm_data_source_f` | 数据管理的修改记录 / 数据源目录 |
| `ads.ads_llm_sys_user_f` / `ads.ads_llm_sys_session_f` | 平台用户（密码以 scrypt 哈希存储）/ 登录会话 |
| `ads.ads_llm_lbl_project_f` / `ads.ads_llm_lbl_requirement_f` | 标注项目 / 标注需求（指定数据、标注标准、状态流转时间） |
| `ads.ads_llm_lbl_chunk_f` / `ads.ads_llm_lbl_item_f` | 分块 / 标注条目（引用源数据行，修改后的内容存在 `label_content`） |
| `ads.ads_llm_lbl_comment_f` / `ads.ads_llm_lbl_delivery_f` / `ads.ads_llm_lbl_action_log_f` | 审核意见 / 交付记录 / 操作日志 |
| `ads.ads_llm_gen_model_f` / `ads.ads_llm_gen_spec_f` | AI 生成：模型配置 / 数据规格 |
| `ads.ads_llm_gen_prompt_f` / `ads.ads_llm_gen_prompt_version_f` / `ads.ads_llm_gen_dict_f` | AI 生成：提示词（当前版本）/ 提示词历史版本 / 业务字典 |
| `ads.ads_llm_gen_task_f` / `ads.ads_llm_gen_task_log_f` | AI 生成：生成任务 / 任务日志 |
| `ads.ads_llm_gen_asset_f` / `ads.ads_llm_gen_conversation_f` / `ads.ads_llm_gen_sample_f` | AI 生成：资产 / 会话（标注条目引用 `conv_row_id`）/ 训练样本（机器产出与任务变量） |

每张表的建表语句中，字段都带有注释，状态类字段的注释写明了每个取值的含义。可以用 `SELECT sql FROM ads.sqlite_master` 查看。

## 七、测试

```bash
# 需先启动页面；会创建测试数据，请在测试环境运行
python web/scripts/e2e_api.py                           # 标注审核流程
python web/scripts/mock_llm.py 18080 &                  # 本地模拟大模型（不消耗 token）
python web/scripts/e2e_gen.py                           # 数据资产 · AI 生成全流程（会把默认模型指向模拟服务）
python web/scripts/check_tpl_parity.py /path/to/labelumos   # 模板引擎与 Lumos 对拍
```

`e2e_gen.py` 覆盖以下环节：
- 模型：Key 掩码、协议自动探测、错误 Key 提示、429 重试。
- 明细生成：维度筛选、不超目标、导出 CSV。
- 任务控制：停止与续跑。
- AI 预标注：多轮历史对话、导出 JSONL。
- 混合下发：明细会话 + 训练集会话 + 蒸馏数据。
- 标注：
  - 会话编号与轮次不可改。
  - 规格校验拦截。
  - 修正 AI 字段与问题。
  - 两类 AI 再标。
  - 剔除。
- 审核与交付：修正进入样本，历史对话同步更新。
- 基于交付结果再预标注。
- 提示词版本与恢复。
- 删除保护与权限。

`e2e_api.py` 覆盖以下环节：
- 权限隔离。
- 下发切块，校验 12000 条切分为 5000/5000/2000。
- 二次认领拦截。
- 非法修改拦截：限价、非法编码、编码与名称不一致。
- 自动判定「已修正」。
- 提交后锁定，标注员不能再改。
- 抽检条数计算。
- 退回必须填写意见，返修后重新提交。
- 交付前不能下载。
- 有分块未通过时不能交付。
- 下载内容包含人工修正，并剔除无效条目。
- 需求员确认交付。
